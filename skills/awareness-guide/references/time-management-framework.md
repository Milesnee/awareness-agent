# 时间管理四维框架

融入觉察助手的参考框架。核心来自《稀缺》一书的时间稀缺四问题模型。

## 四个维度

### 1. 拉入视野（Bring into View）

**问题**：管窥之见（tunneling）——我们的大脑会自动聚焦眼前紧急的事，忽略重要但不紧急的事。

**原则**：
- 只做最重要的事情，让生命更有质量
- 把重要事项拉入视野，打破管窥

**觉察融入**：晨间引导用户识别「今天最重要的一件事」，把它从模糊的背景拉到眼前。

### 2. 合理规划（Reasonable Planning）

**问题**：缺乏规划导致被动响应，时间被紧急但不重要的事吞噬。

**原则**：
- 最重要的事情只有一件
- 分解任务，把握节奏
- 每天最重要的两小时深度工作

**觉察融入**：晚间引导用户觉察「计划 vs 实际」的偏差，不是复盘绩效，是看见自己的时间去了哪里。

### 3. 节约带宽（Save Bandwidth）

**问题**：决策疲劳——每个决策都消耗认知资源，琐事决策挤占了重要决策的带宽。

**原则**：
- 清单化：把重复决策固化为清单
- 模块化：把复杂任务拆成标准模块
- 规律化：固定时间做固定的事
- 记录化：不依赖记忆，写下来

**觉察融入**：晚间引导用户觉察「今天哪个决策反复纠结了」，识别可以固化为流程的日常决策。

### 4. 构建余闲（Build Slack）

**问题**：日程排满，没有缓冲空间。一旦出现意外，整个系统崩塌。

**原则**：
- 精力管理：不是时间管理，是能量管理
- 安逸时光：留白本身就是生产力
- 为明天的战斗积蓄力量

**觉察融入**：晚间引导用户觉察「今天有没有留白」，不评判、不要求，只是看见「没有余闲」这件事本身。

---

## 与觉察助手的关系

这个框架**不是要增加一套新系统**。它是在觉察流程中自然嵌入的引导视角。

### 核心洞察：觉察对话本身就是时间记录

用户不需要额外打卡工具。晚间觉察时用户回顾今天做了什么、差在哪——这些回答就是时间数据。aTimeLogger 需要30次点击/天，而觉察对话天然就是数据入口：
- 互动本身有时间戳
- 用户回顾自然包含活动描述、时长感知、投入质量
- 周洞察时聚合为时间使用模式

**觉察即记录，对话即数据。**

### 四维映射

- **拉入视野** → 晨间：帮用户看见今天真正重要的东西
- **合理规划** → 晚间：帮用户看见计划与现实的差距（不评判）
- **节约带宽** → 晚间：帮用户看见决策消耗
- **构建余闲** → 晚间：帮用户看见自己是否允许自己停下来

核心是**觉察**，不是管理。我们不是帮用户做时间管理，是帮用户看见自己与时间的关系。
